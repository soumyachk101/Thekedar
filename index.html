Thekedar (ठेकेदार) Overview

The site supervisor for autonomous AI coding crews. Decomposes complex project goals into modular task specifications, assigns specialist subagents, gates code changes behind independent read-only review, mechanically enforces file scopes via PreToolUse hooks, and maintains a zero-token ledger of every modification.

The Core Engineering Problem Solved

Single long LLM chat sessions inevitably suffer from context window degradation, leading to hallucinated code paths, session state loss upon crashes, and unreliable prompt adherence. Thekedar replaces prompt instructions with deterministic bash-level enforcement.

Rule #1: Push work down the stack. If bash can block an edit, never rely on an LLM prompt.

The 4-Layer Systemic Discipline

  • Layer 4 · Memory: Markdown state on disk (PROJECT_STATE.md, tasks/*.md). Survives session crashes and context clear commands.
  • Layer 3 · Intelligence: 15 specialist subagents executing in fresh LLM context windows. Reviewers operate strictly in read-only mode.
  • Layer 2 · Guard-Rails: Executable bash hooks (scope-guard.sh and secret-guard.sh) intercept tool calls and abort illegal writes with Exit Code 2.
  • Layer 1 · Determinism: Zero-token bash scripts (munshi.sh ledgers and session-brief.sh state injection).

Architectural Discipline

Engineering Principles for Critical Systems

Prompt instructions fail under context pressure. Thekedar shifts enforcement down to deterministic bash hooks.

Mechanical Scope Protection

scope-guard.sh intercepts all Write and Edit tool calls. If an agent attempts to modify a file outside declared scope, bash returns Exit Code 2 and halts the write before disk mutation.

PreToolUse Secret Interceptor

secret-guard.sh regex-scans every edit payload for AWS access keys, private PEM blocks, JWTs, and API tokens. Zero hardcoded secrets touch git history.

Zero-Token Change Ledger

munshi.sh records | time | tool | file | ledgers instantly via PostToolUse hooks, maintaining an audit trail without wasting model context tokens.

Fresh Context Subagent Routing

Rather than relying on a long multi-hour chat that degrades over time, every task dispatches a purpose-built subagent in an unpolluted context window.

Enforced Read-Only Reviewers

Reviewers (error-checker & security-auditor) have Write and Edit tools stripped at the permission level. They inspect diffs hostile-reviewer style but physically cannot modify source code.

Git-Tracked Markdown Memory

Project state persists on disk in PROJECT_STATE.md and tasks/*.md. Survives session crashes, memory purges, and terminal restarts. Simply type continue to resume.

The 15-Member Purpose-Built Agent Architecture

Every agent operates in an unpolluted context window. Read-only reviewers have file mutation tools stripped at the tool allowlist layer.

planner

नक्शा-वाला · Naksha-Wala

Decomposes complex requests into modular task specs with explicit file targets and acceptance criteria.

backend-dev

मिस्त्री · Mistri

Implements APIs, server logic, database scripts, and backend tasks within assigned target files.

frontend-dev

रंग-मिस्त्री · Rang-Mistri

UI components, design systems, responsive layouts, and visual finish.

error-checker

Inspector (Read-Only)

Runs test suites, linters, and type-checkers to verify task changes pass cleanly.

security-auditor

चौकीदार · Chowkidar (Read-Only)

Audits diffs for injection flaws, unauthenticated endpoints, and hardcoded credentials.

frontend-reviewer

Finisher (Read-Only)

Validates visual quality, layout shifts, responsive breakpoints, and UI polish.
