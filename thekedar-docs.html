PreToolUse Scope Enforcement

The Problem & Solution

Why Single-Context Agents Fail

AI coding agents are brilliant for 20 minutes. After turn 40, context pollution causes severe hallucination, forgotten requirements, and unvetted edits.

1. Context Bloat → Hallucination

Give an agent a whole codebase and a vague goal. By turn 40 it's confidently editing non-existent files. Thekedar isolates every task into a fresh subagent context.

2. No Paper Trail

"What did the AI change yesterday?" Git diff shows what, never why or what was deliberately left untouched. Munshi logs every tool edit live at zero token cost.

3. One Agent, Every Hat

The same context window writes backend code, checks security, and reviews UI. It grades its own homework. Thekedar routes work to read-only specialist reviewers.

4. Session Dies, Memory Dies

Crash, /clear, or a new day — the agent restarts from zero. Thekedar stores PROJECT_STATE.md on disk so session-brief.sh auto-resumes instantaneously.

5. Prompting Isn't Enforcement

"Don't touch that file" is a polite request, not a wall. Under context pressure, prompts get ignored. scope-guard.sh intercepts PreToolUse bash calls and says NO.

6. Token Waste

Asking giant models to perform simple logging or status reporting burns money. Thekedar pushes determinism down to zero-token local bash hooks.

Step 1: Naksha-Wala (Planner) Breaks Down Scope

You say: "Build me JWT authentication with rate limiting."

The orchestrator skill detects a multi-file request and invokes planner in a fresh context. It scans the codebase and writes .thekedar/tasks/004-jwt-auth.md detailing declared target files, non-scope boundaries, and acceptance criteria.

Step 2: API Designer Draws Contract

Before any backend developer writes code, api-designer specifies exact request/response schemas, HTTP status codes, and security requirements inside the task file.

Step 3: Mistri (Backend Dev) Implements

backend-dev receives the task file in a clean context. It performs Write and Edit calls strictly targeted at the task's expected files.

Step 4: PreToolUse Guards Intercept Edits

Every single write call triggers scope-guard.sh (rejects out-of-scope files with exit 2) and secret-guard.sh (blocks AWS/JWT/Stripe key leaks). On allowed writes, munshi.sh logs the exact timestamp and file in today's ledger at 0 token cost.

Step 5: Read-Only Reviewers Gate the Task

error-checker runs unit tests; security-auditor inspects vulnerabilities. Both run in parallel, fresh, read-only contexts. If tests fail, a fix loop returns findings back to the doer.

Step 6: Drift Check & Git Checkpoint

drift-check.sh verifies zero unexpected files were modified. The orchestrator writes changes/task-004.md and issues a clean git commit: "thekedar(task-004): JWT middleware".

System Architecture

The 4-Layer Stack Discipline

Design Rule: Push work down the stack. If bash can enforce something, don't spend tokens asking an LLM nicely. If a small context can do a job, never hand it to a polluted one.

Layer 4 — Memory (Markdown on disk, git-tracked)

PROJECT_STATE.md · config.md · tasks/*.md · changes/*.md

Persists knowledge cleanly on disk. Survives crashes, /clear, and session restarts without relying on hidden database daemons.

Layer 3 — Intelligence (Fresh subagent LLM contexts)

Orchestrator · Planner · 6 Doers · 6 Read-Only Reviewers

Every subagent gets a targeted, clean context. Structural tool restrictions prevent gatekeepers from altering code during reviews.

Layer 2 — Guard-Rails (Bash PreToolUse — ONLY layer allowed to say NO)

scope-guard.sh · secret-guard.sh

Intercepts tool invocations before writes land on disk. Exit 2 capability mechanically blocks unauthorized modifications and key leaks.

Layer 1 — Determinism (Bash, zero tokens, never blocks)

munshi.sh ledger · session-brief.sh · drift-check.sh · Git commits

Executes fast, deterministic logging and brief injections. Completely token-free, running on local system bash.

PreToolUse Guards

Mechanical Scope & Secret Enforcement

Layer 2 is the headline feature in v2. While prompts can be forgotten, bash hooks execute before a tool call lands on disk.

1. scope-guard.sh

Intercepts Write, Edit, and MultiEdit calls. Canonicalizes paths to eliminate ../ bypasses and checks them against the active task's ## Expected files list.


SCOPE-GUARD REJECTED: src/auth/secret.ts is outside task 004's declared scope.

2. secret-guard.sh

Scans only newly proposed edit content for 9 high-confidence secret patterns (AWS keys, PEM private keys, JWTs, GitHub/Slack/Stripe/Anthropic/Google API tokens).


SECRET-GUARD REJECTED: High-confidence AWS secret pattern detected in proposed write.

Non-Negotiable Contract: Fail Open Safety

If jq or python3 is missing, or if an unreadable task file is encountered, the guards exit 0 (allow write) rather than risk bricking your developer session. A bug costs one uncaught edit, never a locked terminal.

Command System

Catalog-Driven Engine

The Agent Factory (v3 Ready)

Thekedar scales gracefully without prompt decay. The crew is generated and validated mechanically from catalog TSV files.

1. TSV Master Catalog

Single source of truth in catalog/agents.tsv defining agent names, models, tool rules, knowledge pack references, and trigger conditions.

2. Deterministic Generators

gen-agent.sh and gen-agent-docs.sh turn catalog rows into validated frontmatter skeletons and documentation automatically.

3. Hard Validation Gates

validate-all.sh enforces bidirectional zero-orphan integrity. A catalog row without an agent file, or an agent without a catalog entry, fails CI instantly.

Questions & Answers

Frequently Asked Questions

What does Thekedar cost in token consumption?
Estimated token usage is 2–4× a raw single-session request for structured work. However, because subagent contexts remain small and targeted, you avoid the massive token waste caused by context bloat and hallucination fix loops in long sessions.
Does scope-guard mean the AI cannot touch unapproved files?
Yes. While an active task is running, scope-guard.sh intercepts any Write or Edit targeted outside the declared files and exits 2, rejecting the write at the bash runtime level.
Does Thekedar require node, npm, or python packages?
Zero dependencies ever. Thekedar relies purely on standard system bash, git, and markdown files. Hooks fail open gracefully even without jq or python3.
Can I use Thekedar in other AI editors like Cursor, Windsurf, or Copilot?
Yes! Run scripts/export-agents-md.sh to generate a single AGENTS.md file that flattens the crew rules into a format compatible with Cursor, Windsurf, Codex, and Copilot.
